# Paiements

## Créer un paiement

```bash
POST /v1/payments
```

```json
{
  "provider": "MONCASH",
  "amount": 500,
  "currency": "HTG",
  "reference": "order_123",
  "description": "Commande de t-shirt"
}
```

Envoyez un en-tête `Idempotency-Key` avec un UUID généré côté client pour relancer une
requête en toute sécurité sans créer de paiement en double.

Réponse :

```json
{
  "id": "d290f1ee-...",
  "status": "PENDING",
  "provider": "MONCASH",
  "amount": 500,
  "currency": "HTG",
  "reference": "order_123",
  "checkoutUrl": "https://...",
  "mode": "TEST",
  "createdAt": "2026-09-21T12:00:00.000Z"
}
```

## Consulter le statut d'un paiement

```bash
GET /v1/payments/:id
```

## Lister les paiements

```bash
GET /v1/payments?status=SUCCEEDED&provider=MONCASH
```

## Simuler un paiement (sandbox uniquement)

Avec une clé **TEST**, faites passer un paiement à un état final directement, sans attendre
le callback d'un vrai fournisseur :

```bash
POST /v1/sandbox/payments/:id/simulate
```

```json
{ "outcome": "success" }
```

Cela déclenche le même processus de livraison de webhooks qu'un vrai règlement.

Essayez tout le parcours de manière interactive dans la [console](/docs/console).
